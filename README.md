# إدارة العنابر — فصل الملفات وتجهيز Supabase

## الملفات
- `index.html`: الواجهة العربية.
- `css/style.css`: كل التنسيقات المنقولة من HTML.
- `js/app.js`: منطق الواجهة الأصلي.
- `js/supabase.js`: عميل Supabase، تسجيل الدخول، التحقق من المالك، عمليات CRUD عامة ورفع ملفات العقود.
- `sql/schema.sql`: مخطط قاعدة البيانات المرسل.

## إعداد Supabase
1. افتح مشروعك في Supabase ثم SQL Editor.
2. راجع `sql/schema.sql` وشغّله مرة واحدة في مشروع جديد فقط. إذا كنت شغّلت المخطط مسبقًا، لا تعِد تشغيله عشوائيًا؛ نفّذ فقط التعديلات الناقصة.
3. أنشئ مستخدمًا من Authentication ثم أضفه إلى قائمة المالكين بتعديل البريد في الاستعلام التالي وتشغيله في SQL Editor:

```sql
insert into private.app_owners (user_id)
select id from auth.users
where lower(email) = lower('YOUR_EMAIL@example.com')
on conflict (user_id) do nothing;
```

4. من Project Settings → API انسخ Project URL و`anon`/publishable key فقط، وضعهما في أول `js/supabase.js` بدل القيم الوهمية. لا تستخدم `service_role` أو secret key في المتصفح.
5. افتح المشروع عبر خادم محلي (مثل Live Server)، وليس عبر `file://`، ثم سجّل الدخول بحساب المالك.

## تنبيه مهم بخصوص الربط
تم فصل CSS وإضافة طبقة Supabase تشمل المصادقة، والتحقق من صلاحية المالك، ودوال القراءة/الإضافة/التعديل/الحذف ورفع ملفات العقود. لكن `js/app.js` ما زال يحتفظ بمنطق الواجهة الأصلي ويستخدم `localStorage`؛ لم يتم تحويل جميع أزرار الواجهة تلقائيًا إلى CRUD على جداول Supabase بعد. لا تعتبر بيانات الواجهة متزامنة مع السحابة قبل ربط كل إجراء بالجداول المناسبة.

## ملاحظات توافق قاعدة البيانات
- الجداول تستخدم UUID بينما المنطق القديم يستخدم `Date.now()` كمعرّفات؛ يلزم تغيير عمليات إنشاء/تعديل العقود والعمال إلى UUID وإدارة العلاقات.
- صور العقود القديمة محفوظة كـ data URL في المتصفح. مخزن `contract-files` خاص، لذلك يجب تخزين مسار الملف واستخدام signed URL للعرض.
- صلاحيات RLS تظل مطلوبة حتى مع فحص المالك في الواجهة؛ لا تعتمد على JavaScript كحاجز أمني.
